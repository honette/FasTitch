複数の画像を放り込んだら、右側にどんどん連結して1枚にしたい。
1つ目の画像を基準に Height は揃える。
連結後の画像のアスペクト比が 16:9 より横長にならないように自動調整する。
自動調整っていうのは、各画像の左右をトリミングして細くすること。

機能は最小限でいい。
Windows 11 で起動できるアプリ (.exe) にする。
FasTrim と同じく Python + PySide6 + Pillow、UI は英語。
アプリ名は FasTitch。Windows での作業は Git Bash 前提。

流れ:
- 画像を複数ドロップ（または開く）。並びはドロップ順。左のサムネイルであとから並べ替え
- 1枚目の高さに、あとの画像の高さを拡大縮小で合わせる（上下クロップしない）
- 隙間なしで横に連結する
- 連結結果が 16:9 より横長なら、各画像を同じ幅になるよう中央から左右均等に切る
- 1枚の画像として別名保存。元ファイルは上書きしない

決まっていること:
- 並び順: ドロップ順。あとからサムネイルをドラッグ（または Ctrl+Up/Down）で並べ替え
- 高さ揃え: 拡大縮小。1枚目の高さに合わせる。拡大も縮小もある
- 左右トリム: 中央基準で均等のみ。寄せは無し
- 16:9 を超えるとき: 完成幅は高さ×16/9 を超えない整数幅。それを枚数で割った幅を各パネルの上限とし、上限より広い画像は中央でその幅にトリムする（削るピクセル数は画像ごとに違う）
- 上限より細い画像はトリムせず、その幅のまま残す。細い分は問題にしない（エラーにしない）
- 最初から 16:9 以下（幅/高さ ≤ 16/9）ならトリムしない。このときは幅を揃えず、高さ揃え後の幅のまま連結する
- 1枚目自体がすでに 16:9 より横長ならエラーで拒否（保存しない）。並び替えで1枚目が変わったときも同じ判定
- 等幅トリムはしない（上限より広い画像だけを上限幅に切る）
- 画像の間の隙間はなし
- 保存名のデフォルト: 1枚目の stem + `_stitched.jpg`、1枚目と同じフォルダ
- 衝突したら `foo_stitched_2.jpg` のように連番。元ファイルは触らない
- 保存名のサフィックス、保存先サブフォルダ、出力形式（JPEG / PNG / WebP）は設定画面で変更可能
- プレビューは保存結果そのもの（トリム後）。パネル境界に区切り線だけ入れる
- 左にサムネイルリスト、右にプレビュー。空のときは Drop images。Delete で除外
